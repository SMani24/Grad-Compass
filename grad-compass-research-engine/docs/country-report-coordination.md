# Country report coordinator instructions

Dave owns routing and release decisions; Marry owns technical compatibility and transport; Ali owns research/corrections; Alex owns independent review. Apply these instructions alongside the ordinary execution contract. No authority, scope, exchange 1.0.0 or private-wire format changes are introduced.

Dave/coordinators must also apply [Task sequencing](../../grad-compass-workspace/design/ordinary-country-workflow.md#task-sequencing) when routing the generated app handoff. This repository guidance is an instruction reference, not an installed live-agent configuration or an enforced control-plane constraint.

## Readiness and event routing

1. Verify exact immutable handoff readiness: request/brief/result identities, both edition revisions/hashes, map and metadata hashes, accessibility and predecessor lineage. Store generated private bindings only in established owner-private runtime/profile output storage. Frozen profiles and intake remain read-only; never write generated bindings into intake. Public coordination uses opaque identities and sanitized dispositions.
2. Keep preparation readiness separate from factual acceptance. A preparation-only child can complete when its stated handoff acceptance is met; a combined producer/correction task can stay open while its delivered version is reviewed. Never mark research accepted to force checkout.
3. Before routing each ready version to Alex, read actual dependencies. The review task must not wait for closure of the producer/correction task waiting for that same review. Producer corrections likewise must not wait for reviewer closure. Remove only a verified stale completion edge through the authorized supported API, or use a distinct completed preparation milestone. Retain parent/delivery/release dependencies and issue parentage. Never clear every dependency indiscriminately.
4. Route one exact-version handoff event with index digest, edition identities, prior review identity and bounded correction scope. Use existing tasks where permitted; do not duplicate research or the app request. Preserve old bytes and verdicts. Record the real reviewer checkout/run and actual new verdict separately from readiness repair. Wait on child/interaction events, not polling or indefinite retries. If no immutable input exists, use a preparation child as the first-class blocker; avoid a completion dependency on a combined task awaiting this review.
5. Alex returns factual support, usefulness and readability verdicts for each exact edition and reconciles metadata. Ali supplies new immutable bytes for required corrections and emits another exact-version event. A task marked done records its stated deliverable, not automatic factual or human approval.

At the exact preparation handoff, reconcile downstream dependencies as well as reviewer dependencies: a preparation milestone may close once its stated immutable handoff is verified, so downstream receipt/validation does not acquire a second wait for a combined producer task awaiting review. Preserve the independent review, parent acceptance, publication and release gates; do not close a combined research task before its own acceptance criteria are met. Record the saved graph and distinguish preparation completion, actual review verdict, ordered result-chain receipt and release disposition in the final acceptance readback.

## Transport and release checkpoints

Marry reconciles acknowledgement and actual result-store receipts independently of editorial/package release. Verify r1 receipt and predecessor digest before r2 transport; preserve ordered history and reconcile uncertain outcomes before resend. Respect current issue gates: a receipt-needed validation cycle requires coordinator reconciliation, never a publisher bypass. Publisher checks, result receipt, package publication, factual disposition, and exact-version human approval remain separate records. Dave retains release disposition and final board communication. Human approval remains not_requested until a genuine authorized record exists.

## Conflicts and failure evidence

Use only documented supported APIs with authentication and the current run header. Read current status/version, assignee, checkoutRunId, executionRunId, dependencies and execution policy before a changed-state action. Use revision preconditions where supported (document baseRevisionId); do not invent unsupported version fields. Never retry a checkout 409, overwrite another run, unpause an agent or bypass quotas/approval. On a mutation 409 capture HTTP status, response body/error code, operation, UTC time and originating run; redact credentials and applicant data. Read the issue/run/version again and inspect the actual cause before any necessary, newly justified supported action. No blind retry. Verify saved dependencies and successful checkout separately; neither proves review completion.

For a permanent control-plane failure, stop mutation and escalate the actual error/run/version evidence to the operator via Dave. Keep a first-class blocker or allowed unblock descriptor with the responsible agent and exact action. A missing historical response body is an explicit diagnostic limitation, not proof of a particular conflict subtype. Preserve rollback evidence: before/after edge lists, exact changed resource and readback; restore only authorized changes if necessary, preserving unrelated relationships.
