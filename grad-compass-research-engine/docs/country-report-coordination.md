# Country report coordinator instructions

Dave owns routing and release decisions; Marry owns technical compatibility and transport; Ali owns research/corrections; Alex owns independent review. Apply these instructions alongside the ordinary execution contract. No authority, scope, exchange 1.0.0 or private-wire format changes are introduced.

Dave/coordinators must also apply [Task sequencing](../../grad-compass-workspace/design/ordinary-country-workflow.md#task-sequencing) when routing the generated app handoff. This repository guidance is an instruction reference, not an installed live-agent configuration or an enforced control-plane constraint.

## Readiness and event routing

1. Verify exact immutable handoff readiness: request/brief/result identities, both edition revisions/hashes, map and metadata hashes, accessibility and predecessor lineage. Store generated private bindings only in established owner-private runtime/profile output storage. Frozen profiles and intake remain read-only; never write generated bindings into intake. Public coordination uses opaque identities and sanitized dispositions.
2. Keep preparation readiness separate from factual acceptance. A preparation-only child can complete when its stated handoff acceptance is met; a combined producer/correction task can stay open while its delivered version is reviewed. Never mark research accepted to force checkout.
3. Before routing each ready version to Alex, read actual dependencies. The review task must not wait for closure of the producer/correction task waiting for that same review. Producer corrections likewise must not wait for reviewer closure. Remove only a verified stale completion edge through the authorized supported API, or use a distinct completed preparation milestone. Retain parent/delivery/release dependencies and issue parentage. Never clear every dependency indiscriminately.
4. Route one exact-version handoff event with index digest, edition identities, prior review identity and bounded correction scope. Use existing tasks where permitted; do not duplicate research or the app request. Preserve old bytes and verdicts. Record the real reviewer checkout/run and actual new verdict separately from readiness repair. Wait on child/interaction events, not polling or indefinite retries. If no immutable input exists, use a preparation child as the first-class blocker; avoid a completion dependency on a combined task awaiting this review.
5. Alex returns factual support, usefulness and readability verdicts for each exact edition and reconciles metadata. Ali supplies new immutable bytes for required corrections and emits another exact-version event. A task marked done records its stated deliverable, not automatic factual or human approval.

At the exact preparation handoff, reconcile downstream dependencies as well as reviewer dependencies: a preparation milestone may close once its stated immutable handoff is verified, so downstream receipt/validation does not acquire a second wait for a combined producer task awaiting review. Preserve the independent review, parent acceptance, publication and release gates; do not close a combined research task before its own acceptance criteria are met. Record the saved graph and distinguish preparation completion, actual review verdict, ordered result-chain receipt and release disposition in the final acceptance readback.

### Ordinary delivery and targeted engineering acceptance

For unchanged data-only country deliveries, bounded research fulfilment concludes after the required reviewed content and assets, exact release authorization, compatible package publication, genuine consumer receipts and replay, and preservation checks are satisfied. These deliveries do not automatically require a fresh developer GUI gate. Research/review, receipt/publication and external app verification are separate evidence states bound to exact released identities. This distinction does not relax substantive, asset, release, receipt or explicitly requested acceptance gates; retain the required asset provenance, hash and package-membership checks. Apply this distinction to future task graphs without requiring a manual chat wake for each country.

Engineering UI, PDF or launcher changes, or a concrete display defect, retain targeted exact native verification by an actually capable app team. Demonstrate rendering and authorized configured-export capability; adapter=codex_local, DISPLAY availability or filesystem visibility alone is insufficient. Codex owns generated app handoff, design and harness work. Reuse the existing private handoff and recorded receipts rather than repeating factual review or publication, creating capability loops or retrying Alex's harness. Native evidence must bind the exact released detailed/reader/photo rendering, PDF and Markdown output, actual configured export directory, restart/replay and before/after preservation inventory captured before launch. Marry validates returned private evidence; Dave retains routing, final acceptance and board communication. Never claim unperformed verification.

An explicitly requested existing native acceptance step is not waived by this ordinary-delivery distinction. Until its exact final evidence is returned and validated, record awaiting app verification, with no native pass. Reconcile a pending access interaction only through supported workflow with history preserved after actual evidence satisfies its technical requirement; a routing comment is not an answer.

## Conflicts and failure evidence

Use only documented supported APIs with authentication and the current run header. Read current status/version, assignee, checkoutRunId, executionRunId, dependencies and execution policy before a changed-state action. Use revision preconditions where supported (document baseRevisionId); do not invent unsupported version fields. Never retry a checkout 409, overwrite another run, unpause an agent or bypass quotas/approval. On a mutation 409 capture HTTP status, response body/error code, operation, UTC time and originating run; redact credentials and applicant data. Read the issue/run/version again and inspect the actual cause before any necessary, newly justified supported action. No blind retry. Verify saved dependencies and successful checkout separately; neither proves review completion.

For a permanent control-plane failure, stop mutation and escalate the actual error/run/version evidence to the operator via Dave. Keep a first-class blocker or allowed unblock descriptor with the responsible agent and exact action. A missing historical response body is an explicit diagnostic limitation, not proof of a particular conflict subtype. Preserve rollback evidence: before/after edge lists, exact changed resource and readback; restore only authorized changes if necessary, preserving unrelated relationships.

## All-country batch acceptance checklist

Maintain a row for every authorized country with owner, actual stage state and exact next action for sources, licensed offline photo, editorial editions, independent review, validation, release and delivery. Track evidence date, future-year fee uncertainty, personal eligibility and human approval separately. Unknown future fees or personal eligibility alone do not keep accepted bounded work indefinitely partial. A batch is finished only when every required country deliverable has acceptance or an authorized explicit disposition.

Before requesting release, verify:

- Exact saved request and predecessor result identities/digests; preserve existing request and released revisions. New result revisions follow actual stored lineage, never only an app success marker.
- Per-country immutable detailed/reader/map/metadata/index hashes, source bindings and licensed offline photo bytes; or genuine bounded failure evidence with Dave's disposition. Source/photo stages apply to ALL countries, including reused work.
- Alex's actual exact-byte factual support, usefulness and readability records, asset provenance/accuracy/attribution review, and matching metadata. Older reviews remain historical; human approval remains not_requested absent a real exact-version authorization.
- Fresh focused validator and publisher check results, before/after artifact inventory and preservation of old editions/results/annotations. Obtain Dave's release disposition for the exact hashes BEFORE publication.
- Actual package and result receipts, ordered chain, normal-path app acceptance and replay preservation after authorized delivery. Apply [Ordinary delivery and targeted engineering acceptance](#ordinary-delivery-and-targeted-engineering-acceptance): unchanged data-only deliveries do not automatically acquire a fresh developer GUI gate; targeted engineering, concrete display defects and explicit native acceptance steps require Codex native UI, screen/PDF and actual configured export-directory evidence. Never assume a directory. Failure/retry tests use marked disposable profiles only.

Use the supported optional asset representation; coordinate any necessary extension with Codex before shared contract edits. Codex owns app-generated assignment wording and country/batch display; give Codex this acceptance language without editing consumer code. Keep preparation milestones independent of review so ready exact versions can be routed on their delivered-index event. Producer correction follow-ups stay executable without reviewer closure. Record exact release identities and remaining owner/action on the parent for Dave's final board communication. Private intake stays solely in the established access-controlled store.
